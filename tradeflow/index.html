Schema View SQL Schema

Six tables: industry and factor are shared reference tables (sector definitions, 721 environmental factors); trade and trade_factor hold international flows and their environmental coefficients per country/flow_type; interstate and interstate_factor hold US state-to-state (BEA) flows. Each database covers a single year, so these tables carry no year column. Each table's box shows column names and types.

The diagram's columns come from two sources: a hardcoded static schema (in this page's JS and mirrored in the Rust API) used as an instant preview, and the live database schema (queried from Postgres information_schema.columns) once the API responds. The two can drift out of sync — that's why a column can briefly appear then disappear (as happened with a leftover id column already removed from the live tables but not yet from the static fallbacks).

Indexes

Indexes aren't arbitrary — each one mirrors a real join or filter the app performs:

  • Composite lookup indexes on (trade_id, country, flow_type) for trade and trade_factor — this is the exact compound key used to join those tables, since trade_id alone repeats across countries/flow types.
  • Filter-column indexes on country, region1/region2 (trade), state1/state2 (interstate — US state codes, not Exiobase regions), and flow_type — these back the country/region/state/flow-type selections made in this page's UI (year selects which per-year database to query, not a column filter).
  • Foreign-key indexes on factor_id (both fact tables → factor) and interstate_id (self-lookup within interstate_factor). interstate_factor also keeps trade_id — interstate_id's embedded industry is only a broad category, not the industry1/industry2 pair, and interstate has no interstate_id column to join through — so trade_id is the only reliable path back to the originating flow's exact industry pair.
  • Natural-key dedup constraints: trade on (region1, region2, industry1, industry2) — the true identity of a flow, so the same flow pulled from two different country-perspective CSV runs (e.g. "imports to US" and "exports from Canada" both capturing the same CA→US leg) collapses into one row instead of duplicating. interstate on (state1, state2, industry1, industry2) — including same-state (state1 == state2) rows, which represent genuine intrastate flow, not duplicates.

Loading asynchronously

The diagram used to wait on a fetch to the Rust API (/api/db/industry-schema) before drawing anything, so a slow or unresponsive database made the whole page feel stalled. Now it draws immediately using the static schema, then fetches the live schema in the background and re-renders — adding real row counts and the ⋮ per-table menu once that data arrives.
